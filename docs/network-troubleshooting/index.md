# 电脑网络问题与排障全书：设置了代理却不能上网？七大常见故障深度排查大系

> **【Answer-First 急救速查表】**  
> - **症状 1：关掉翻墙软件后，电脑彻底打不开网页，微信却能发消息？**  
>   👉 **原因与解法**：Windows 注册表中的系统代理开关未被客户端自动关闭。按下 `Win + R` 输入 `inetcpl.cpl`，在「连接 → 局域网设置」中取消勾选「为 LAN 使用代理服务器」即可 1 秒恢复。  
> - **症状 2：客户端启动报错「listen tcp 127.0.0.1:7890: bind: address already in use」？**  
>   👉 **原因与解法**：7890 端口被冲突进程占用。在客户端设置中将 Mixed Port 更改为 `7899` 或 `10808`。  
> - **症状 3：所有节点测速全部超时（Timeout 或 -1ms）？**  
>   👉 **原因与解法**：检查电脑本地系统时钟误差是否超过 90 秒；检查本地防火墙是否拦截了 Mihomo/Xray 核心进程。  
> - **症状 4：为什么同一条订阅手机秒连，电脑却死活连不上？**  
>   👉 **原因与解法**：手机是全系统透明 VPN 接管，而电脑依赖系统代理与驱动。在电脑客户端中**开启 TUN 虚拟网卡模式**即可彻底对齐手机体验。

## 二、七大核心网络故障深度拆解与实操修复

### 故障 1：关掉翻墙工具后，浏览器提示「代理服务器拒绝连接 (ERR_PROXY_CONNECTION_FAILED)」
- **底层成因**：正常情况下，客户端在退出时会调用 Windows API 将系统的代理设置抹除。但如果电脑突然死机、重启、或在任务管理器中强制杀掉了客户端进程，Windows 会继续将所有出站流量发往 `127.0.0.1:7890`。由于此时后台已经没有监听程序，浏览器直接报错拒绝连接。
- **终极急救方案**：
  1. 按下快捷键 `Win + I` 打开 Windows 设置。
  2. 进入「网络和 Internet」→「代理」。
  3. 在「手动设置代理」下方，找到「使用代理服务器」，将其开关切换为 **【关】**。
  4. 或者按下 `Win + R` 输入 `inetcpl.cpl`，在「连接 → 局域网设置」中取消勾选「为 LAN 使用代理服务器」。

---

### 故障 2：为什么同一条机场订阅手机秒连，电脑却死活连不上？
这是新手最为高频的困惑，主要源于电脑与手机的系统网络底层存在巨大鸿沟：

| 影响因素 | 手机系统 (iOS / Android) | 电脑系统 (Windows / macOS) |
| :--- | :--- | :--- |
| **底层接管机制** | 原生 `VpnService` 强行接管整机所有网络包 | 默认只有应用层「系统代理」，命令行与网游不走代理 |
| **本地安全环境** | 沙箱严格，极少存在端口抢占与驱动拦截 | 存在复杂的第三方杀毒软件（360/火绒/Defender）拦截 |
| **系统时间机制** | 依赖运营商基站 NTP 纳秒级自动校准 | 主板纽扣电池老化容易产生几分钟的时间偏差导致 TLS 失败 |
| **解决对策** | 默认开箱即用 | **必须在电脑端安装服务模式并开启 TUN 虚拟网卡** |

---

### 故障 3：电脑系统时间误差导致的 TLS 握手全面死锁
- **底层成因**：现代加密协议（VLESS / Trojan / HTTPS）全面采用强安全时效验证，以防止黑客的重放攻击。如果您的 Windows 电脑主板时钟比真实网络时间快了或慢了超过 90 秒，海外服务器在收到请求时会认为该连接请求是一个过期的非法重放包，直接丢弃，表现为所有节点测速全红报 Error。
- **修复对策**：右键 Windows 右下角时间，选择「调整日期和时间」，点击「立即同步」，确保与国家授时中心同步。

---

### 故障 4：本地 7890 / 7897 端口冲突报错
- **底层成因**：由于 7890 是各大 Clash 系客户端的默认端口，若后台遗留了未完全退出的旧进程，新启动的客户端将无法绑定该端口，并在内核日志中打印 `bind: address already in use`。
- **命令行诊断与查杀**：
```powershell
# 查询占用 7890 端口的进程 PID
netstat -ano | findstr :7890

# 强制终止该占用进程 (假设 PID 为 1234)
taskkill /F /PID 1234
```
或者直接在客户端界面将端口修改为不常用的 `7899` 或 `10808`。

---

### 故障 5：DNS 污染与本地 Hosts 文件被锁死
- **底层成因**：某些历史流氓软件或破解补丁曾在 `C:\Windows\System32\drivers\etc\hosts` 中强行写入了将 `google.com` 映射到 `127.0.0.1` 的死循环记录。
- **修复对策**：用记事本打开 hosts 文件，删除所有与国外网站相关的条目并保存；然后以管理员身份运行 PowerShell 执行：
```powershell
ipconfig /flushdns
```

---

### 故障 6：微信与国内软件频繁提示异地登录或直接转圈
- **底层成因**：误将代理模式设置为了 **「全局模式 (Global)」**。在全局模式下，微信的登录连接被转发至香港或美国节点，微信安全系统识别为异常跨国登录，从而触发人脸识别与异地封锁。
- **修复对策**：客户端主界面必须始终保持为 **「规则模式 (Rule)」**。

---

### 故障 7：Windows 终极网络堆栈大重置（彻底断网急救）
如果电脑经历了严重网络篡改，导致无论开不开代理都彻底断网，可以使用 Windows 官方底层网络复位命令：
```powershell
# 1. 重置 Windows 套接字目录
netsh winsock reset

# 2. 重置 TCP/IP 协议堆栈
netsh int ip reset

# 3. 冲刷 DNS 缓存
ipconfig /flushdns

# 执行完毕后重启电脑
shutdown -r -t 0
```
